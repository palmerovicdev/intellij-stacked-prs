### T8 — Add Layer must not jump to the top of the screen
Findings (javap on 263's `intellij.platform.ide.impl.jar`): `DialogWrapperPeerImpl.MyDialog.setSize/setBounds/pack` all go through `fitToScreen(rect)` (`ScreenUtil.fitToScreen` → `moveRectangleToFitTheScreen`), and `setLocation(rect.x, rect.y)` when it moved it. A dialog only goes to the very top when a requested height does not fit the screen. On a matching name the dialog is resized twice: `AddLayerDialog.update()` → `pack()`, then `WrappingText.fitWindow()` → `window.setSize(width, preferredHeight)` from `componentResized`. Suspect: one of them asks for a transient huge height (a wrapped `JTextArea` measured at a tiny width gives many lines), the dialog is moved to the top, then shrunk back → flicker + jump.
1. Evidence first (headless tests have no real window): the platform logs every requested size and fitted rectangle at debug level. The user enables `#com.intellij.openapi.ui.impl.DialogWrapperPeerImpl` and `#com.intellij.openapi.ui.DialogWrapper` in *Help → Diagnostic Tools → Debug Log Settings…*, reproduces once; I read `~/Library/Logs/JetBrains/IntelliJIdea2026.3/idea.log`.
2. Fix where the log points. Expected shape: one resize path for the whole dialog, after the layout settles (`invokeLater`), that only grows the height to the preferred height at the current width and keeps x/y; `update()` stops calling `pack()` for this, and `WrappingText` uses the same path (it is shared by other dialogs, so their behavior is checked too — Risk item 3 if it changes).
3. Test: the window position cannot be tested headless (exception to RED). A unit test pins what can be: the height asked for after the note appears is the preferred height at the dialog's real width, never larger than that.
